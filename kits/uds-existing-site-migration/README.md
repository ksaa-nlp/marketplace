# حزمة ترحيل واجهة موقع قائم

مرجع وأدوات مساندة لترحيل واجهة موجودة تدريجيًا إلى كود المنصات مع المحافظة على وظائفها. هذا المجلد **حزمة مرجعية، وليس إضافة Claude Code ثالثة**؛ لا بيان plugin ولا تسجيل جديد في marketplace ولا مهارة تنافس `dga-design`.

## أي مسار أستخدم؟

- لتدقيق تصميم الواجهة أو تطبيقه داخل Claude Code: استخدم [`dga-design`](../../plugins/dga-design/)، وهي إضافة التصميم القائمة في السوق.
- إذا كان لديك موقع قائم وتحتاج الجرد وخطة الدفعات وأدوات التحقق المرفقة: ارجع إلى هذه الحزمة كمادة مساندة، وطبّق قرارات التصميم عبر مسار المشروع المعتمد.
- أعمال التطوير العامة تبقى ضمن أدوات المشروع وإضافة `ksaa-ai-dev` إذا كانت مثبّتة. لا تفرض هذه الحزمة قواعد التصميم على أعمال backend أو المهام غير المتعلقة بالواجهة.

لا تدمج أعداد أو معرفات قواعد الحزمة مع قائمة `dga-design` بوصفها قائمة رسمية واحدة. عند التعارض، راجع المصدر الرسمي الحالي وتعليمات المشروع وسجّل القرار قبل التطبيق.

## الملفات الأصلية

```text
assets/original/
├── Saudi-UDS-Existing-Site-Migration-Kit-2026-09-28.zip
└── README_START_HERE_AR.md
```

المرفقان محفوظان دون تعديل محتواهما. الأرشيف يحتوي على 37 ملفًا: المراجع والسجلات، أدوات Python، المثال، تعليمات AGENTS، ولقطات الموارد الرسمية. هذا التنظيم لا يستبعد ملفًا من الأرشيف ولا يعيد تسمية ملفاته الداخلية. راجع [المصدر والتحقق](provenance.md) لبصمات الملفات ونتائج الاختبارات.

الملفات داخل ZIP لا تُحمّل تلقائيًا كتعليمات للمستودع ولا تُنفّذ عند تثبيت أي إضافة. لقطات `official-resources/site-assets/` مواد مرجعية؛ ليست اعتماديات تشغيلية ولا حزمة مكونات للمشروع.

## الاستخدام الآمن

1. اقرأ هذا الدليل ثم README الأصلي. فك الأرشيف في مجلد عمل منفصل عن مشروعك، وافحص الملفات قبل استخدامها. لا تشغّل حزم JavaScript الملتقطة من الموقع.
2. اقرأ `AGENTS.md` و`CLAUDE.md` الموجودين في المشروع القائم أولًا. **لا تنسخ AGENTS.md المرفق فوق الملف القائم.** إنه نموذج مرجعي؛ ادمج البنود المنطبقة يدويًا بعد مراجعتها مع الحفاظ على تعليمات المشروع ونطاق المهمة.
3. افحص حالة Git واعمل في فرع منفصل. قارن `.design-system/` و`tools/uds-compliance/` بالمسارات الموجودة قبل النقل. انسخ غير الموجود فقط أو ادمج التعارضات صراحةً؛ لا تستخدم استبدالًا جماعيًا.
4. ابدأ بجرد المكونات المشتركة واستخداماتها والأنماط والاختبارات. حدد القواعد والقوالب المنطبقة على النطاق، واكتب خطة ومخاطر وطريقة رجوع لكل دفعة قبل تعديل الواجهة.
5. نفّذ تدريجيًا: ربط tokens، الخطوط، المكونات المشتركة، ثم الصفحات. حافظ على props والأحداث وAPI وbackend وأسماء الحقول ومسارات التنقل ومنطق الأعمال. أي تغيير وظيفي أو معماري خارج الطلب يحتاج قرارًا منفصلًا من صاحب المشروع.
6. شغّل اختبارات المشروع والفحص المناسب بعد كل دفعة. راجع كل FAIL وWARNING وأكمل الفحوص اليدوية المنطبقة. لا تعدّل المشروع لإرضاء إنذار كاذب.

تعليمات النسخ في README الأصلي تعكس طريقة استخدام المرفق قبل التغليف. **دمج تعليمات المشروع والمحافظة على الملفات القائمة مطلوبان، ولا يعني إرفاق الأصل اعتماد الاستبدال المباشر.**

## تشغيل اختبارات الحزمة

بعد فكها، ومن داخل `Saudi-UDS-Existing-Site-Migration-Kit/`:

```bash
python3 tools/uds-compliance/test_uds_compliance.py
python3 tools/uds-compliance/uds_compliance.py uds-validation-demo --strict
```

لمقارنة التوليد، استخدم نسخة مؤقتة: المولدات التالية تكتب السجلات، فلا تشغّلها فوق تغييرات غير محفوظة:

```bash
python3 tools/uds-compliance/build_rules.py
python3 tools/uds-compliance/build_catalogs.py
```

لا تحتاج هذه الاختبارات إلى اتصال بالشبكة أو حزم Python إضافية. لا حاجة إلى تشغيل ملفات `official-resources/site-assets/` لإتمامها. المثال HTML الأصلي يشير إلى Google Fonts؛ فتحه في المتصفح قد يجلب الخط خارجيًا، وقد تتغير النتيجة البصرية عند عدم توفره.

## ما تثبته النتائج وما لا تثبته

أعيد محليًا التحقق من 169 قاعدة فريدة و50 مدخل مكونات و19 مدخل قوالب. نجحت الاختبارات الخمسة، وكانت أربعة ملفات التوليد مطابقة بايتًا للمرفق. فحص المثال أعاد 25 PASS، صفر FAIL، صفر WARNING، و144 MANUAL REVIEW.

هذه سجلات وصفية واختبارات محدودة، وليست 169 اختبارًا آليًا أو مكتبة مكونات تنفيذية. تاريخ المصادر في الحزمة 2026-09-07؛ الفحص المحلي بتاريخ 2026-10-05 لا يعني إعادة التحقق من جميع المصادر الحية أو تأكيد صحة كل قاعدة.

- المدقق يستخدم HTMLParser وأنماطًا ساكنة؛ ليس محلل React أو متصفحًا. JSX/TSX قد ينتجان إنذارات كاذبة لأن ملف المكون لا يحتوي html/meta. افحص الصفحة المعروضة أو HTML مُصدّرًا عند الحاجة.
- يدعم HTML/HTM/CSS/SCSS/JSX/TSX فقط. Vue/Svelte وJavaScript الخالص غير مدعومين مباشرة. يستبعد `dist` و`build` و`node_modules` وغيرها؛ افحص عدد ومسارات الملفات في التقرير. المسار الخاطئ أو غياب الملفات ليس نجاحًا ولو عاد الأمر برمز صفر دون `--strict`.
- PASS يعني غياب مخالفة اكتشفها النمط؛ قد لا يكون المكون موجودًا أصلًا. لا يثبت التفاعل أو التباين المحسوب أو الوصول أو الاستجابة.
- 100 قاعدة شبه آلية و44 قاعدة يدوية تبقى بحاجة إلى أدلة منطبقة. لم تُجرَ مراجعة بصرية أو متصفح أو قارئ شاشة أو مشروع إنتاجي في فحص التغليف.
- ميّز REQUIRED وRECOMMENDED وOPTIONAL وINFERRED. لا تعمم قاعدة خارج نطاقها، ولا تملأ NOT PUBLISHED BY OFFICIAL SOURCE بتخمين منسوب إلى المصدر الرسمي.
- `--uds-*` أسماء محلية مستنتجة في المرفق، وليست أسماء API رسمية. لا تعتمد حزمة أو إصدارًا أو أمر تثبيت تاريخيًا دون التحقق من المصدر الحالي.

أي تقييم ناتج هو تقييم داخلي محدود بالنطاق والأدلة، وليس شهادة امتثال أو اعتمادًا من هيئة الحكومة الرقمية.
