# feature-test-report

مهارة تقرأ مواصفة ميزة، وتكتب سيناريوهات اختبار لكل متطلب فيها، وتتحقق أيّها تغطيه الاختبارات القائمة، وتشغّل تلك الاختبارات، ثم تكتب تقريرًا يبدأ بالحكم: هل الميزة جاهزة للإصدار؟ تعمل في أي مشروع أيًّا كانت لغته وإطار اختباره.

## الاستعمال

بعد تثبيت الإضافة (`/plugin install feature-test-report@ksaa-nlp`):

```
/feature-test-report:feature-test-report docs/specs/checkout.md   ← بمسار المواصفة
/feature-test-report:feature-test-report                          ← تبحث عن مواصفة الميزة التي سمّيتها
```

ويستدعيها Claude تلقائيًا إذا طلبت سيناريوهات اختبار أو تقرير اختبار لميزة.

## ما تفعله

1. تتعرف على المشروع: مكان المواصفات، وأنماط ملفات الاختبار، وأوامر التشغيل، من إعدادات المشروع أو من المستودع نفسه.
2. تستخرج المتطلبات من المواصفة مع مرجع القسم لكل واحد.
3. تكتب السيناريوهات: المسار الطبيعي، ومسارات الفشل، والحدود، والوصول بكل دور، والتكرار.
4. تطابق المواصفة بالكود وتدوّن الاختلافات.
5. تربط كل سيناريو بدليله: Automated أو Partial أو Manual أو None.
6. تشغّل الاختبارات المذكورة وتسجّل Pass أو Fail أو Not run.
7. تكتب التقرير في `docs/test-reports/<feature-slug>-<YYYY-MM-DD>.md`.

لا تغيّر كود المنتج ولا تضيف اختبارات إلا إذا طُلب منها ذلك.

## إعدادات المشروع (اختيارية)

المهارة تستنتج ما تحتاجه من المستودع. لتثبيته في مشروع معيّن، انسخ [`project-config-example.md`](skills/feature-test-report/project-config-example.md) إلى `.claude/feature-test-report.md` في ذلك المشروع واملأ ما ينطبق: مسارات المواصفات، وأنماط الاختبارات، وأوامر التشغيل، والأدوار، والمزالق المعروفة، ومجلد التقرير ولغته. ما في هذا الملف له الأولوية على الاستنتاج.
