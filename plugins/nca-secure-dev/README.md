# nca-secure-dev

مهارة تطبّق متطلبات الهيئة الوطنية للأمن السيبراني (NCA) على المشروع أو تدقّقه عليها، ثم تكتب تقرير التزام عربيًّا يقرأه مراجع الأمن السيبراني ويحكم منه: كم ضابطًا مستوفى بدليل، وما الفجوات، ومن يعالج كل فجوة.

## الاستعمال

بعد تثبيت الإضافة (`/plugin install nca-secure-dev@ksaa-nlp`):

```
/nca-secure-dev:nca-secure-dev افحص المشروع حسب متطلبات الهيئة   ← تدقيق مشروع قائم (AUDIT)
/nca-secure-dev:nca-secure-dev                                   ← يستنتج الوضع من سياق المهمة
```

ويستدعيها Claude تلقائيًا عند طلب فحص أو مراجعة أو تدقيق امتثال، وعند كتابة كود جديد يلزمه الالتزام بالضوابط.

## الأوضاع الثلاثة

| الوضع | متى | ماذا يفعل |
|---|---|---|
| **AUDIT** | طلب فحص أو مراجعة مشروع قائم | قراءة فقط: لا يعدّل سطرًا واحدًا من كود المشروع، ولا يكتب إلا داخل `compliance/` |
| **BUILD** | كتابة ميزة أو كود جديد | يطبّق الضوابط أثناء الكتابة ويحدّث التقرير بعد كل تغيير أمني |
| **FIX** | بعد التدقيق، عند طلب المعالجة | يعالج الفجوات بالأولوية (الحرجة أولًا) ويحدّث حالة كل ضابط بدليله الجديد |

## ما يُخرجه

`compliance/NCA-COMPLIANCE-REPORT.md` — تقرير عربي يُعرض من اليمين إلى اليسار، فيه:

- جدول ضوابط مفصّل، لكل ضابط: رقمه، وحالته (✅ ملتزم · 🟡 جزئي · ❌ غير ملتزم · ❓ يحتاج تحقق · 🏢 مسؤولية الجهة · ➖ لا ينطبق)، ودليله بصيغة `ملف:سطر` أو أمر يشغّله المراجع، وعمودان فارغان لقرار المراجع.
- خطة معالجة مرتّبة بالأولوية والمسؤول المقترح.
- نتائج الفحص الآلي، والأدلة محفوظة في `compliance/evidence/`.
- قسم «ما لم يُراجع» — إلزامي في وضع التدقيق، حتى لا يُقرأ التقرير كتغطية كاملة.

## الأطر المرجعية

ECC-2:2024 (الجهات الحكومية والبنى التحتية الحساسة) · NCNICC-1:2025 (القطاع الخاص غير المصنّف، فئة أ/ب) · NCS-2:2025 (المعايير الوطنية للتشفير) · نموذجا الهيئة لمعيار التطوير الآمن وحماية تطبيقات الويب · ويُضاف ما ينطبق: CCC و CSCC و DCC و PDPL/NDMO.

المهارة تتحقق من موقع الهيئة من وجود إصدار أحدث قبل الاعتماد على القائمة، وتسجّل الإصدار المطبّق في التقرير.

## الخريطة

- `skills/nca-secure-dev/SKILL.md` ← سير العمل: اختيار الوضع، ثم النطاق، ثم الفحص، ثم التقرير، وقواعد الأمانة في تعبئته.
- `skills/nca-secure-dev/references/frameworks.md` ← الأطر وإصداراتها السارية وما هو مسودة.
- `skills/nca-secure-dev/references/dev-checklist.md` ← قائمة المطوّر مربوطة بأرقام الضوابط.
- `skills/nca-secure-dev/references/audit-playbook.md` ← دليل تدقيق مشروع قائم: ماذا تقرأ، وبأي أنماط تبحث، وما الذي يُعدّ فجوة لا مجرد أثر.
- `skills/nca-secure-dev/references/secure-patterns.md` ← نمط ❌ ونمط ✅ لكل مجال، مع الإصلاح الموصى به.
- `skills/nca-secure-dev/assets/compliance-report-template.md` ← قالب التقرير.
- `skills/nca-secure-dev/scripts/nca-scan.sh` ← جمع الأدلة آليًّا: يكتشف المكدس، ويشغّل ما هو مثبّت من الفواحص، ويحفظ المخرجات في `compliance/evidence/`. للقراءة فقط، ولا يثبّت شيئًا ولا يعدّل المشروع.

## حدود المهارة

التقرير **تقييم ذاتي** يحتاج تحقق موظف الأمن السيبراني: المهارة لا تمنح شهادة امتثال ولا تقرر أن المشروع ملتزم — تقرير بعدد الضوابط المستوفاة بدليل، والحكم للجهة أو للهيئة. وما لا يظهر في الكود (جدار حماية الويب، الشبكة، SIEM، النسخ الاحتياطي، الضوابط التنظيمية) يُعلَّم ❓ أو 🏢 ليؤكده فريق البنية التحتية أو الجهة، لا يُفترض.
