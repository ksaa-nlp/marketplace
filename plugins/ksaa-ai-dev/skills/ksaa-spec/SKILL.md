# مواصفة قابلة للاختبار

1. اقرأ تعليمات المشروع ومواصفاته الحالية وسلوك الكود المتصل بالطلب عبر [دليل السياق](../../references/project-context.md). احتفظ بمعرفات المتطلبات ومصدر الحقيقة القائم.
2. حدد المشكلة والقيمة والمستخدم والدور والمسار الأساسي والنطاق وخارجه والقيود والافتراضات والأخطاء والبيانات والأمان. استخدم [قالب الميزة](../../templates/feature-spec.md) ولا تخترع رقمًا أو صلاحية أو تبعية.
3. اختر أسئلة المجال ذات الصلة من [جودة اللغة](../../references/language-quality.md) أو [جودة الألعاب](../../references/game-quality.md). وجود مثال هنا ليس دليلًا على قدرة موجودة بالمشروع.
4. امنح كل معيار قبول معرفًا ونتيجة مرصودة وحالة إيجابية وسلبية أو حدية واختبارًا مناسبًا؛ اربطها عبر [سلسلة التتبع](../../templates/traceability.md).
5. اعرض أسئلة المنتج المانعة مع خيارات وأثر ومالك قرار وفق [بوابات القرار](../../references/decision-gates.md). أنجز الأجزاء الواضحة؛ لا تحول افتراضًا إلى موافقة ولا تبدأ تنفيذ الجزء الغامض.

**مثال فقط:** عند نسخ لعبة، اسأل هل تشمل النسخة المحتوى أو النتائج وما حالة نشرها ومن يعدلها. لا تفترض الإجابة من اسم الميزة.

**المخرج:** مواصفة مسودة وأسئلة مانعة ومعايير واختبارات مقترحة؛ الاعتماد الحقيقي له مرجع وصاحب قرار.
