# بوابات CI قابلة للتحقق

1. اقرأ إعدادات CI وworkspace وأوامر الحزم الفعلية ومتغيرات البناء المقصودة ووجود ملفات التهيئة المشار إليها. استخدم [البوابات الثماني](../../references/quality-gates.md)، وافصل كون الوظيفة معرفة عن كونها نُفذت ومنعت الدمج فعلًا.
2. اربط كل بوابة بوظيفتها وأمرها ونطاقها وعتبتها وأثرها ودليلها ومالكها؛ اختر صيغة تحقق غير معدلة عند وجود `--fix` وفق أدوات المشروع. لا تعمم أمرًا أو runtime أو بيئة من مشروع آخر.
3. تحقق قراءةً من الفحوص المطلوبة وحماية الفرع/البيئة وحالات الاستثناء إن توفرت صلاحية القراءة. الملف الإرشادي أو YAML وحده ليس دليلًا على إنفاذ الحماية. الإعداد غير المتاح يسجل غير متحقق.
4. قبل تعديل pipeline أو بيئة أو إعداد أسرار أو حماية، طبق [بوابات القرار](../../references/decision-gates.md). طلب تصميم خطة لا يجيز تمكينها. لا تعطل فحصًا أو تحوله اختياريًا لجعل المسار أخضر.
5. تحقق من الإعداد بالوسيلة المحلية المعتمدة، ثم من run للنسخة المحددة إن كان مصرحًا ومتاحًا. سجّل passed وfailed وskipped وnot-run بدقة، وأعد الفحص بعد إصلاح مأذون. راجع النتائج البشرية والأمنية منفصلة عن نتائج الآلة.

**المخرج:** خريطة بوابات ووظائف وأدلة وحماية فعلية/غير متحققة، وفرق إعدادات فقط إذا طلب وأجيز؛ لا ادعاء نشر أو حماية مطبقة من دون دليل.
