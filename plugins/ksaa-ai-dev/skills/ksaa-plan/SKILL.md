# خطة تنفيذ دون تعديل الكود

1. اقرأ المواصفة المقبولة والكود ذي الصلة و[سياق المشروع](../../references/project-context.md). إذا كان معيار جوهري غائبًا، اقترح استكماله بمهارة المواصفة قبل التخمين.
2. ارسم تدفق السلوك وحدود البيانات ومصدر الحقيقة والمستهلكين. اكتشف وجود المحتوى أو API أو الفهرس أو جولة اللعبة بدل افتراضها جميعًا.
3. قسم العمل إلى مهام قابلة للمراجعة؛ لكل منها هدف، ملفات متوقعة، اعتماديات، معيار قبول، اختبار، خطر وإمكان تراجع. ضمّن الوثائق والعقود المولدة والبناء المستهدف عند تأثرها.
4. افصل القرارات المعمارية وأعمال قاعدة البيانات والتبعيات والصلاحيات وCI والنشر إلى نقاط انتظار صريحة وفق [بوابات القرار](../../references/decision-gates.md). لا تختزل الموافقة على الخطة في موافقة تنفيذ كل إجراء مؤثر.
5. حدد ترتيبًا يسمح بالعمل المستقل المصرح به وما يبقى ثابتًا. لا تعدل كودًا أو إعدادات لمجرد طلب خطة؛ اكتف بمخرج الخطة في الوجهة التي طلبها المستخدم.

**المخرج:** مهمة، هدف، ملفات متوقعة، اعتماديات، اختبار، مخاطرة، قرار مطلوب ومالك؛ ثم ترتيب التنفيذ والفجوات.
