# البوابات الثماني ودليل التنفيذ

هذه خريطة تحقق وليست ادعاء أن المشروع يملك الأدوات أو أن الفحوص تعمل. اختر الأمر والعتبة والبيئة من المشروع نفسه؛ الأداة المفقودة تسجل غير مهيأة/غير منفذة وتمنع إعلان اكتمال البوابة الملزمة. قائمة Markdown لا تنشئ required checks أو حماية فرع.

| معرف البوابة | البوابة | الدليل المطلوب |
| --- | --- | --- |
| lint | الأسلوب والفحص المحلي | أمر تحقق فعلي ونطاقه ونتيجته؛ البناء والأنواع والتنسيق بحسب المكدس، مع فحص أثر `--fix` |
| unit | اختبارات الوحدة | حالات قواعد ومعايير وحدود تمنع سلوكًا خاطئًا، ونتيجة تنفيذ؛ إنشاء المكون وحده غير كافٍ |
| integration | التكامل | حدود مكونات/خدمات وبيانات اصطناعية؛ رحلة واجهة/E2E عند تأثرها، مع تمييز mock الوحدة عنها |
| sast | التحليل الأمني الساكن | أداة معتمدة وتقرير للنسخة وتقييم النتائج؛ استثناء بشري موثق إذا سمحت السياسة |
| dependency | التبعيات | ثغرات وتراخيص وملاءمة وصيانة واستقرار، ومبرر البدائل للتبعية الجديدة؛ فحص ثغرات لا يثبت الرخصة |
| secrets | كشف الأسرار | فحص الفرق والملفات/السجلات المناسبة دون طباعة القيم، ومسار احتواء إن ظهرت |
| human-review | مراجعة بشرية | شخص مؤهل وقرار حقيقي يراجع المنطق والمعمارية والأمان والاختبارات والافتراضات والصيانة والدين التقني |
| ci-cd | إنفاذ التكامل/التسليم | run للنسخة وفحوص مطلوبة وحماية متحققة تمنع الدمج/النشر عند الفشل؛ YAML وحده لا يكفي |

## سجل موحد

لكل بوابة: النسخة، النطاق، الأمر ومجلد العمل أو طريقة المراجعة، البيئة، وقت التنفيذ، النتيجة/رمز الخروج، رابط/أثر الدليل والمالك. الحالات: `passed` ناجح، `failed` فاشل، `not-run` غير منفذ، `blocked` متعذر، `skipped` متجاوز، و`exception` استثناء معتمد منفصل عن النجاح. غير منطبق يحتاج تبرير واعتماد سياسة؛ لا يحول الغياب إلى نجاح.

وجود أمر في package أو CI ليس تنفيذه. وجود اختبار في المواصفة ليس كود اختبار، وكتابته ليست نجاحه. لا تجمع دليلًا من commit قديم مع حكم على نسخة جديدة. قيّم تغطية المعايير مع الإنسان، لا العدد وحده.

## سير المرور

السياق والمواصفة → فحوص محلية ووحدة → أمن وتبعيات وأسرار → PR ومراجعة بشرية → CI/CD → staging → قرار إصدار مخول → إنتاج عبر المسار المسموح. يمكن إجراء الفحوص المستقلة بالتوازي؛ فشل الملزم يمنع التقدم ويتبع [إجراء التوقف والإصلاح](decision-gates.md).

لا تعطل بوابة لنجاح شكلي. احتفظ بنتيجة الفشل مع الإصلاح وإعادة التشغيل؛ قبول مشروط لا يلغي بندًا حرجًا مانعًا. الاختبار الآلي لا يعتمد صحة لغوية تحتاج مختصًا أو يمنح قرار دمج.

## أداة الاتساق الاختيارية

انسخ [مثال أدلة البوابات](../templates/gate-evidence.json) إلى مكان محلي للمشروع واملأه بمراجع حقيقية. شغّل `python3 scripts/check-gate-evidence.py <ملف-الأدلة>` من جذر الإضافة. الأداة تفحص اكتمال واتساق السجل المعلن والنسخة والتواريخ وحالات الفشل؛ لا تشغل CI ولا تصادق على صحة الروابط أو هوية المراجع ولا تمنح إذن دمج أو نشر. المثال غير منفذ عمدًا، ويجب أن يفشل حتى اكتمال الأدلة. راجع السياسة والفحوص الفعلية حتى إن خرجت الأداة بنجاح.
