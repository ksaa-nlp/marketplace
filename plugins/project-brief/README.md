# project-brief

مهارة تحفظ شرح المشروع للناس في ملفات Markdown وملف إعداد JSON يملكها المشروع: ما المشكلة، وما الفكرة، وأين وصلنا، وما الذي لم نتحقق منه بعد. ثم تجمع منها عند الطلب مادة ملخص تنفيذي أو عرض أو تقرير أو سيناريو عرض أو ملحق خصائص، لجمهور ووجهة نظر ولغة يحددها المشروع. تصلح للبرمجيات والبحث والخدمات والأفكار التي لم تُنفَّذ بعد.

## الاستعمال

بعد تثبيت الإضافة (`/plugin install project-brief@ksaa-nlp`):

```
/project-brief:project-brief setup                                       ← تجهيز الملخص أول مرة
/project-brief:project-brief جهّز ملخصًا عربيًا للإدارة عن هذا المشروع      ← طلب واحد بلغة طبيعية
/project-brief:project-brief update                                      ← بعد تغيير مؤثر
/project-brief:project-brief check                                       ← فحص بلا تعديل
/project-brief:project-brief export --recipe introduction --language ar  ← مادة لجمهور ووسيلة
/project-brief:project-brief check --root "D:/work/my project" --config docs/project-brief.json
```

ويستدعيها Claude تلقائيًا إذا طلبت إعداد ملخص المشروع أو تحديثه أو فحصه أو تصديره.

## الأوضاع

| الوضع | ما يفعله | ما يكتبه |
|---|---|---|
| `setup` | يقرأ ستة مداخل على الأكثر (README وAGENTS.md وملف البيان وملفات شرح قائمة)، ويعتمد مادة الشرح الموجودة بدل نسخها، ويذكر افتراضاته وما لا يعرفه. وإن وُجد ملف الإعداد لا ينشئ شيئًا | ملفات جديدة فقط، وسطرًا واحدًا في `AGENTS.md` يشير إلى ملف الإعداد |
| `update` | يحدد الموضوعات التي يمسّها تغيير مؤثر ويحسّن شرحها مع حفظ القيود. التغيير الذي لا يمس الشرح لا يغيّر نصًا. والترجمات حسب إعداد المشروع | الموضوعات المتأثرة وحدها |
| `check` | يعرض البنية وتقادم النص والأدلة والترجمات، وما سيفشل عند التصدير | لا شيء |
| `export` | يجمع موضوعات وصفة بلغة محددة في Markdown أو JSON، ويكيّف الصياغة لوسيلة التقديم عند الطلب فقط | لا شيء، أو ملف الناتج حيث تطلب |

تسجيل المراجعة (`review`) لا يحدث إلا حين تقول إنك راجعت موضوعًا ولغة محددين، ويطلب Claude Code إذنك قبله. المراجعة إقرار تحريري، لا تصديق للوقائع.

## ما يملكه المشروع

- `project-brief.json` في جذر المشروع، أو أي مسار تحدده بـ`--config`، وملفات المحتوى التي يشير إليها: `brief.md`، أو ملفات قائمة، أو أقسام داخلها بين علامتي `project-brief:start` و`project-brief:end`.
- لا شيء تحت `.claude/` ولا داخل مجلد الإضافة، فتحديث الإضافة أو حذفها لا يمس المحتوى. وأدوات الوكلاء الأخرى تجد ملف الإعداد بالسطر الذي يضيفه setup في `AGENTS.md`.
- لغة المحتوى يختارها المشروع: العربية أصلًا من البداية، أو ترجمة تُضاف لاحقًا، أو لا عربية أصلًا. كون توثيق الإضافة بالعربية لا يفرض لغة على المحتوى، ولا يلزم المشروع بلغتين.

## بلا Claude

`skills/project-brief/scripts/brief.py` أداة مستقلة: Python 3.8 أو أحدث، بالمكتبة القياسية فقط، بلا شبكة ولا مفاتيح ولا Git. انسخها مع `assets/starter/` و`references/contract.md` (أو `contract.en.md`) إلى أي مشروع، أو اكتفِ بملفات Markdown. التفاصيل في [contract.md](skills/project-brief/references/contract.md).

```sh
python3 brief.py init   --root . --language ar
python3 brief.py check  --root .
python3 brief.py review --root . --topic purpose --language ar --acknowledge-reviewed
python3 brief.py export --root . --recipe introduction --language ar > exports/introduction.ar.md
```

```markdown
# مكتبة الحي المتنقلة

ar · introduction

## مكتبة الحي المتنقلة

**المشكلة:** لا توجد مكتبة عامة على مسافة مشي لأكثر سكان الحي، والأطفال أكثر المتأثرين.

**الفكرة:** عربة كتب تقف أسبوعيًا قرب المدرسة والمسجد، يديرها متطوعون.

**الحالة الراهنة:** جُرّبت ثلاث وقفات في سبتمبر ٢٠٢٦ (مختبَر محليًا: ٤١ إعارة سُجّلت يدويًا). لم يُتفق بعد مع البلدية على موقع دائم (غير معروف).

**القرار التالي:** الموافقة على تجربة لثلاثة أشهر بميزانية الصيانة فقط، مع قياس الإعارات وعدد العائدين.
```

## الحدود

- لا تصنع ملفات PowerPoint أو PDF أو صوتًا، ولا تنشر شيئًا. الناتج Markdown أو JSON، مادةٌ لأداة إخراج لاحقة.
- لا تعيد كتابة الشرح آليًا. إعادة الصياغة بطلب المستخدم، وتبقى مسودة غير مراجعة تحفظ القيود.
- لا تجلب الأدلة الخارجية ولا تتحقق من أن نظامًا يعمل؛ الرابط مرجع لا إثبات.
- `public` قرار تحريري، لا كاشف أسرار.
- `rtl` يصف النص فقط؛ اتجاه العرض والخطوط مسؤولية أداة الإخراج وتُختبر فيها.
- لا hooks ولا عملاء في الخلفية ولا تشغيل دوري ولا فحص للمستودع كله.
- الاختبارات آلية على مشاريع مؤقتة؛ لا تثبت سلوك المهارة في جلسة Claude حقيقية ولا سهولة استعمالها.

## العلاقة بالإضافات الأخرى

لا تعتمد المهارة على أي إضافة. يمكن ربط تقارير `feature-test-report` أدلةً بأعداد Pass وFail وNot run وتاريخ التقرير كما هي، دون إعادة تشغيل الاختبارات ولا تحويل نجاحها إلى ادعاء جاهزية. وتقارير `nca-secure-dev` و`dga-design` و`accessibility-toolbar` تُذكر بوصفها تقييمًا ذاتيًا. ويقيس `skill-overhead` عبء هذه المهارة.
