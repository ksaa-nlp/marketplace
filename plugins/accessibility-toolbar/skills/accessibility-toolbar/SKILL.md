# شريط تفضيلات الإتاحة للمشاريع العربية

ابدأ بتقنية المشروع، ثم كيّف التنفيذ معها. المرجع الجاهز الوحيد المختبر في هذه الحزمة هو React V5 مع Tailwind؛ ملف TSX ليس تنفيذًا عامًا يُنسخ إلى كل إطار. المهارة توجه التكييف، ولا تتضمن نسخ Vue أو Angular أو JavaScript مستقلة مختبرة.

## افحص المشروع قبل اختيار التنفيذ

1. اقرأ تعليمات المشروع والمداخل وملفات الاعتماديات الموجودة. حدد الإطار واللغة وإصداراتهما؛ لا تفترض وجود package.json في مشروع ثابت أو يولّد HTML من الخادم.
2. افحص نظام CSS ومكوّنات التصميم والتوكنات وRTL وسياسة CSP إن وجدت. تحقق هل الألوان كاملة أم مكونات HSL، وكيف تطبق فلاتر الصفحة والتكبير.
3. حدد طريقة العرض: DOM ثابت، تطبيق عميل، SSR/ترطيب، أو صفحات يولّدها الخادم، وكيف تتغير المسارات وتُركّب المكوّنات وتزال.
4. حدد الأداة الموجودة للحوار والنطق والتخزين والاختبار. لا تضف React أو Tailwind أو مكتبة أيقونات لمجرد أن المرجع يستخدمها.
5. اذكر تقنية المشروع والمسار المقترح والاعتماديات اللازمة. اسأل فقط عن معلومات مؤثرة لا يمكن استنتاجها، ثم نفّذ وفق نطاق طلب المستخدم.

إذا كان المشروع React/Tailwind مناسبًا، يمكن دمج المرجع كما في [دليل المرجع](references/react-reference.md). وإلا اقرأ [خطة التكييف والقبول](references/framework-adaptation.md)، وأنتج المكوّن والأنماط وفق أسلوب المشروع الحالي، دون تقديم المرجع TSX كنسخة مدعومة مباشرة لذلك الإطار.

## متطلبات سلوك مستقلة عن الإطار

- استخدم زر HTML أصليًا مسمّى، يدعم Enter وSpace والنقر، مع تركيز مرئي وحالة توسع صحيحة. لا تُعدّ كل نقرة مؤشّرًا على سحب.
- يبدأ السحب بعد حركة مقصودة، ولا يفتح الأداة عند انتهائه. قدّم بديلًا بلوحة المفاتيح مثل Alt + الأسهم، واحصر الموضع المحفوظ ضمن الشاشة عند التحميل والتغيير والتكبير وفق أبعاد الزر الفعلية.
- للحوار اسم واضح ودلالة حوار. ينتقل التركيز إلى عنصر مناسب عند الفتح؛ يعمل Tab وShift+Tab داخله، ويغلق Escape والإغلاق والغطاء وفق السلوك المعتمد، ثم يعود التركيز إلى الفتح أو الإظهار.
- اعزل الخلفية أثناء فتح الحوار أمام التركيز والتفعيل وقارئ الشاشة. احفظ القيم السابقة لـinert/aria-hidden وoverflow وأعدها عند الإغلاق، بما في ذلك عناصر الخلفية المضافة أثناء الفتح. إذا احتاج متصفح مستهدف بديلًا، اختبر فعاليته ولا تعتبر aria-hidden وحده عزلًا للتركيز.
- ضع أدوات الحوار والدليل في طبقة مستقلة عن فلاتر محتوى الموقع، باستعمال آلية الرسم المناسبة للمشروع. لا تضع filter/transform على أسلاف هذه الطبقة بما يفسد fixed. افحص عناصر fixed في محتوى الموقع عند تطبيق الفلاتر عليه.
- اجعل الأدوات قابلة للوصول دون تجاوز أفقي عند عرض 320/375px وتكبير المتصفح 200%/400% وتكبير الصفحة مع النص. عقد المرجع: أزرار ≥44px في العرض والارتفاع، وتسميات الأدوات لا تقل عن 14px عند تقليل نص الصفحة؛ افحص القياس الفعلي.
- طبّق ألوانًا صالحة من توكنات المشروع دون فرض صيغة HSL أو أسماء Tailwind عليه ودون الكتابة فوق تصميم الموقع. اجعل الأوضاع اللونية متبادلة الاستبعاد، ولا تعتبرها ضمان تباين أو تصحيحًا طبيًا.
- ADHD = دليل قراءة وتقليل حركة. وضّح إغلاق اللوحة لمعاينة الدليل، واجعله ظاهرًا ويتبع المؤشر أو التركيز أو التحديد، واحفظ اختياره. لا ادعاء علاجي. الخط البديل يستخدم ما يتاح في المشروع دون ادعاء خط متخصص غير مرفق.
- استخدم Web Speech أو خدمة المشروع المعتمدة عند توافرها. تعامل مع البدء والنهاية والخطأ والإلغاء والإيقاف المؤقت والمتابعة والإيقاف وReset، واحتفظ بحالة نطق موحدة. التحديد الذي لم يتغير مع Tab لا يُنطق مجددًا، ويجب أن يبقى الإيقاف متاحًا لقراءة التحديد. لا تعطل زرًا مركّزًا فتترك التركيز في الخلفية.
- احترم تقليل الحركة من الأداة والنظام، واجعل تمرير القراءة فوريًا عند التفعيل. لا تعتبر احترام تمرير القارئ وحده إيقافًا لكل حركات الموقع.
- غيّر muted فقط عندما يتغير خيار الكتم؛ تعديل النص أو التباعد أو اللون يحافظ على اختيار الزائر لكتم الوسائط.
- خزّن التفضيلات محليًا إن أمكن، وتعامل مع تخزين محظور أو بيانات غير صالحة دون تعطيل الأداة. المفاتيح في المرجع a11y-settings-v2 وa11y-launcher-pos؛ إن غيّرتها للتكييف وثّق التوافق والترحيل. Reset يلغي النطق والعلامات والإعدادات، والموضع مستقل في المرجع.
- اربط أحداث المتصفح والتخزين بعد توفر DOM، لا أثناء عرض الخادم. أزل المستمعات والمؤقتات وألغِ النطق عند إزالة التنفيذ، واستعد حالات الخلفية التي غيّرتها. التزم بنظام المسارات ودورة حياة المشروع.

## موارد التنفيذ ومصدر الثقة

- assets/AccessibilityToolbar.tsx وassets/accessibility.css: مرجع React V5 وCSS المرتبط به، لا اعتماد إلزامي على المشروع الآخر.
- assets/AccessibilityToolbar.test.ts وassets/AccessibilityToolbar.interaction.test.tsx: اختبارات للمرجع React؛ يمكن استلهام الحالات عند كتابة اختبارات للتكييف، لكن لا تنقل نتيجة نجاحها إليه. صوت الوحدة محاكاة فقط.
- [تقرير V4 → V5](references/validation-v5.html): 35 نجاحًا و4 غير مكتملة في المختبر المذكور، وليست نتيجة للمهارة على كل إطار.
- [أفضل ممارسات الموقع](references/best-practices.md): الموقع نفسه يحتاج محتوى ودلالات وتباينًا وسلوكًا ميسّرًا؛ الشريط لا يمنح شهادة WCAG/ADA.

## قبول التكييف وتسليمه

طبّق [خطة القبول](references/framework-adaptation.md) على التنفيذ الفعلي. استخدم أدوات المشروع الحالية لفحص الأنواع والبناء والاختبارات ذات المعنى، ثم اختبر الواجهة في المتصفح وقارئ شاشة حقيقي متاح. سجّل وظيفة غير متاحة كغير متاحة أو غير مختبرة بوضوح؛ لا تعرض نجاحًا مصطنعًا.

سلّم التقنية والإصدارات والملفات والتغييرات، وخطوات الدمج، والاعتماديات الجديدة إن وجدت، وجدول نجاح/فشل/غير مختبر مع الأدلة وخطوات التكرار. ميّز جودة الصوت المسموع عن أحداث API، وفحص AX/DOM عن قارئ الشاشة. لا تعمّم نتائج المرجع React على التكييف أو الموقع ولا تعتبر صفر مخالفات آلية شهادة مطابقة.
